# Roles and Entities

## Роли пользователей (UI / API)

### admin

- Полный доступ: все хосты, создание/редактирование/удаление правил алертов, управление пользователями (если реализовано).
- Может создавать хосты и выдавать токены агентам.
- Доступ ко всем эндпоинтам чтения (hosts, metrics, processes, alerts) без ограничения по host_id.

### user

- Просмотр только назначенных хостов/проектов (если в модели есть привязка user → hosts или user → project → hosts).
- В MVP можно упростить: один пользователь = доступ ко всем хостам; разграничение admin/user — только для будущего расширения (управление правилами, настройками).

## Сущность Host

- **Идентификация:** по токену агента. Backend хранит `token_hash`; при ingest проверяет Bearer token (hash сравнивается constant-time).
- **last_seen_at:** обновляется при каждом успешном POST /v1/ingest. Используется для:
  - отображения статуса online/offline (например online ⇔ last_seen_at > now() - 2× interval_sec);
  - правила алерта host_down (срабатывает, если last_seen_at старше порога).
- **Регистрация хоста:** admin создаёт запись host (name, os, arch, tags), генерирует токен (один раз показывается пользователю), сохраняет token_hash. Агент получает host_id и токен через конфиг (вручную или через отдельный endpoint выдачи токена).

## Аутентификация

- **Agent → Backend:** Bearer token (host token), один токен на хост.
- **User → Backend:** JWT (access token) или session cookie (httpOnly). В MVP достаточно JWT в памяти после login; при необходимости — refresh token и ротация.
