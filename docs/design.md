# Design: частоты сбора и хранения

## Частоты сбора (Agent)

| Источник | Интервал | Обоснование |
|----------|----------|-------------|
| Raw metrics (CPU, RAM, load, net, disk) | **10 s** | Компромисс между детализацией и нагрузкой на агент и сеть; достаточно для графиков и алертов |
| Processes (top-N) | **30 s** | Реже, т.к. чтение /proc тяжёлое; top-10 по CPU + top-10 по RSS или объединённый top-15 |

## Объёмы (Processes)

- **Top-N:** top-10 по CPU и top-10 по RSS, либо объединённый топ-15 по комбинированному критерию (чтобы не дублировать одни и те же процессы).
- Сбор не чаще одного раза в 30 секунд.

## Retention (хранение)

| Таблица / слой | Срок хранения | Обоснование |
|----------------|----------------|-------------|
| metrics_raw | **30 дней** | Детальные данные для отладки и коротких периодов |
| metrics_1m (1-минутные агрегаты) | **90 дней** | Средняя детализация для дашбордов |
| metrics_5m, metrics_1h | **180 дней** | Долгосрочные тренды, отчёты |
| proc_snapshots | **7–14 дней** | Срезы процессов для анализа «кто съел CPU» в недавнем прошлом |

## Резолюции для API

- **raw** — выборка из metrics_raw (для периодов ≤ 1–2 часов).
- **1m** — из metrics_1m для периодов > 1 часа (рекомендуется по умолчанию для 6h/24h/7d).
- **5m** — из metrics_5m для длинных диапазонов (опционально).

## Jitter

Агент добавляет небольшой случайный jitter к интервалу сбора (например ±1–2 s), чтобы множество агентов не слали батчи одновременно на сервер.
